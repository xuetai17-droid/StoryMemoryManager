# 剧情自动记忆 Story Memory Manager

版本：0.4.1

SillyTavern 长线 RP 自动记忆扩展。安装一次，可用于不同角色卡和不同聊天；记忆按“聊天”隔离。

## 功能

- 每个聊天独立记忆，避免角色卡之间串台。
- 自动增量总结；默认每 8 条新消息触发一次。
- 可重新扫描整条旧聊天。
- 可导入/导出 JSON。
- 独立维护“剧情时间”，不把 SillyTavern 楼层发送时间当成剧情时间。
- 时间优先级：用户正文明确时间 > 相对时间推进 > 连续事件 > AI `<date>`。
- 保存时间线、事实、事件、人物、关系、未完成事项、冲突和隔离记忆。
- 使用当前 SillyTavern 已连接的模型做后台总结，不在本插件保存 API Key。
- 在正常生成前临时注入当前聊天记忆。

## 当前这条旧剧情的第一次使用

1. 安装并启用本扩展。
2. 打开目标聊天。
3. 点击右下角“记忆”。
4. 点“导入记忆 JSON”。
5. 选择已经清洗好的 `剧情主记忆_清洗重建版_v2.json`。
6. 确认面板显示当前剧情时间为 `2025-09-21 02:25`。
7. 保持“生成时自动注入记忆”和“自动增量总结”开启。
8. 继续正常聊天即可。

## 新角色卡 / 新聊天

不需要导入旧 JSON。打开新聊天后直接开始聊天，插件会在达到触发条数后建立自己的记忆。也可以手动点“总结新增”。

## 注意

- LLM 总结不能保证绝对无误，因此插件保留 `conflicts` 和 `quarantined`。
- “重扫整条聊天”不会删除原始聊天，只重建本插件存在 chatMetadata 里的记忆。
- 如果当前模型/后端不支持 Structured Outputs，插件会自动尝试普通 JSON 输出作为回退。
- 第三方扩展有执行前端 JavaScript 的权限，只应安装你信任的扩展。

## 文件

- `manifest.json`：SillyTavern 扩展声明。
- `index.js`：核心逻辑。
- `style.css`：移动端友好界面。

## v0.2.10 元指令冲突过滤

- USER 的重写、修改、OOC、文风/格式/生成规则等元指令不再作为剧情事实冲突。
- 模型明确标记为“用户修改请求 / 非正文事实 / 元指令”等的 conflict/quarantined 会在写入前过滤。
- 真正的剧情时间线、人物关系、事件事实矛盾仍保留冲突/隔离检测，并可触发历史重建自动暂停。


## v0.2.12 时序状态变化过滤

- 重新定义 `conflicts`：只有“同一时间点、同一事实维度、无法同时成立”的已确认事实才属于真正冲突。
- 前后时序中的地点移动、关系发展、情绪变化、行为变化、玩法升级、计划更新等不再触发冲突暂停。
- 对模型误报的“剧情演进型冲突”增加二次过滤；被过滤项只写入审计记录，不污染 `conflicts`。
- `quarantined` 继续作为“待后文确认”的候选事实保存，但不会中断历史重建。
- 只有新增真正 `conflicts` 时才自动暂停。


## v0.2.13 时间修正与月份锁

- 新增“时间修正”：输入错误日期与正确日期，可修正当前聊天插件记忆中的对应日期；不会修改 SillyTavern 原聊天。
- 修正范围包括当前剧情时间、当前场景、时间线、事件、未完成事项及其他插件记忆字段中完全匹配的日期文本。
- 新增月份锁：没有新增原始聊天中的明确跨月证据，不允许模型自行改变月份。
- 单独的“17日/周五/早晨”等时间信息继承当前可靠月份。
- AI `<date>` 为低优先级证据，不得单独造成跨月、倒退或大跨度日期跳跃。

## v0.3.0 完整整合版

本版本将此前分散的修正合并为一个版本：

- 剧情起点锁定：建立记忆后，剧情起点成为硬锚点，模型总结不能自行覆盖。
- 缺失日期检查：从剧情起点到当前剧情日期逐日检查；无记录日期只标记待检查，不自动编造剧情。
- 历史记忆浏览器：支持关键词搜索以及时间线 / 人物 / 人物关系 / 未完成事项类型筛选。
- 人物归并显示：同一主人物只显示一个折叠框；已知 Xue Ling / 薛伶 归一为薛伶。
- 人物关系归并显示：同一对人物只显示一个关系框，并保留关系发展记录。
- 未完成事项整理：隐藏 loop_ 内部 ID，按未来事件 / 进行中 / 悬而未决 / 过期待确认分类。
- 保留同一天时间线合并、日期与时间自动排序。
- 保留折叠式时间修正工具。
- 不修改原始聊天；上述归并主要作用于记忆管理与显示层，避免破坏已有记忆。


## v0.4.0 数据结构重构版

### 1. 标准化数据结构
- 新增 v4 schema。
- 时间线改为按日期 `days[YYYY-MM-DD]` 保存。
- 人物改为唯一 ID + 主名称 + aliases。
- 稳定人物资料与当前状态分开；地点、衣着、身体状态等不再无限堆叠。
- 双人关系使用唯一 relation ID；多人同场信息不再自动拼接成人物关系。
- 待办改为严格模式，只迁移/保留明确未来且尚未完成的任务。

### 2. 一次性旧记忆迁移
- 新增“数据重构”按钮。
- 执行前自动把完整旧记忆保存到聊天 metadata 的 legacy backup。
- 迁移不会修改 SillyTavern 原聊天。
- 无日期时间线、多人物关系等可疑数据进入隔离区供人工检查。

### 3. 待办严格模式
只保留：
- 明确预约
- 明确未来会面
- 明确未来课程/任务
- 明确截止事项

不再把以下内容长期当待办：
- 已发生的剧情
- 进行中的亲密互动
- 已结束的课程/会面/讨论
- 单纯“尚未回答/等待回应”
- 已确认的人物关系变化

### 4. 历史记忆浏览器
在 v4 数据上搜索时间线、人物、双人关系和待办，不再把原始杂乱 JSON 直接堆在结果中。

### 5. 剧情日期
剧情起点继续锁定。当前剧情时间要求保留具体日期；学期/星期/时段仅作为附加描述。

- 不修改原始 SillyTavern 聊天。
