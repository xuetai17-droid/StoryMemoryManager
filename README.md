# Story Memory Manager v0.11.26 HYBRID

本版集中更新三项：当前剧情时间追踪、移动端注入诊断界面、阶段大总结。



## v0.11.26 阶段大总结稳定性收口

- 阶段大总结改为“一个确定窗口 = 一个宏观阶段”的稳定管线，不再要求模型返回 `stages` 数组或自行切 1–3 段，避免不同后端把根对象/数组包装成不同形态。
- 单组最多 30 条已确认 timeline；source 范围、日期范围由 SMM 本地确定，模型不再负责边界字段。
- 兼容模型直接返回单个阶段对象、`stages`/`chapters` 数组以及常见 `value/data/result` 包装。
- 每一组独立容错：模型输出为空、非 JSON、字段包装异常、Profile 请求失败或超时，都不会再让整次 1700+ 楼阶段总结报废。该组会切换为“本地事实保底”，只从现有 canonical timeline/open_loops 抽取，不编造新事实。
- 连续两组 AI 输出异常时，本轮开启熔断：剩余窗口直接使用本地事实保底，避免反复烧 Token 和连续弹错；下一次手动“更新阶段大总结”会重新尝试 AI，可把保底阶段升级为 AI 阶段。
- 阶段浏览器会标记“本地事实保底”，便于人工核对；主模型注入格式不变。
- 失败安全边界不变：不重扫原聊天、不修改 JSONL、不清空旧 memory；只有完整阶段集合构建完成后才一次性写入。


## v0.11.24 独立总结结构化输出与预设隔离

- 独立总结 Profile 请求不再加载保存的聊天/RP generation preset，避免角色扮演预设干扰 JSON-only 总结任务。
- Chat Completion Profile 在提供 `jsonSchema` 时把 schema 透传给 SillyTavern `ConnectionManagerRequestService.sendRequest(..., overridePayload)`，启用原生结构化 JSON 请求。
- 兼容 SillyTavern 在结构化输出时把 `response.content` 直接返回为对象的情况，会安全序列化后交给现有 JSON 校验链。
- 保留 v0.11.23 的 reasoning JSON 恢复作为兜底；reasoning 只有普通推理文本时仍不会写入长期记忆。
- 不改动原聊天 JSONL，不重建旧记忆，不改变 v0.11.21 已通过的剧情时间/地点解析。

## v0.11.23 独立总结 Profile 空正文热修复

- 修复独立总结 Profile 请求成功、但 SillyTavern 将结果放在 `reasoning` 而 `content` 为空时，SMM 误报“Profile 返回为空”的问题。
- SMM 仍优先读取最终 `content`；只有最终正文为空、且 reasoning 中存在可本地解析/修复的 JSON 对象时，才将 reasoning 作为恢复来源。
- 不会把普通推理 prose 直接写进 canonical memory；reasoning 不能解析为 JSON 时仍按失败处理并保留旧结果。
- 同时兼容 `message.content`、`choices[0].message.content` 等非标准包装，避免对象型 `message` 被错误转换成 `[object Object]`。
- 不改 v0.11.22 已通过的时间/地点追踪、界面和阶段总结结构。

## v0.11.22 阶段大总结 JSON 热修复

- 修复阶段大总结模型在 `summary` 等文本字段中输出未转义 ASCII 双引号时，`JSON.parse` 与旧本地修复均失败的问题。
- 本地修复现在会识别“字符串内容里的裸双引号”和真正的 JSON 结构闭合引号，只转义前者。
- 不再全局把中文弯引号 `“ ”` 转成 ASCII 双引号，避免原本合法的中文引用反而被修坏。
- 阶段大总结提示增加标准 JSON 约束：引用称呼/原话优先使用 `「」` 或中文弯引号，降低后端再次产生裸双引号的概率。
- 阶段大总结失败提示改为短错误摘要；完整响应预览只保留在浏览器控制台，避免手机端出现覆盖大半屏的红色错误块。
- 该修复不会重扫原聊天、不会清空 memory、不会修改 JSONL；失败的这一次没有写入阶段总结，可升级后直接重新点击生成。

## 1. 当前剧情时间 / 地点追踪

- 新增轻量 current-state resolver：同一/相邻状态证据优先采用最近可靠 canonical 正文；如果后续楼层只有可靠 `/世界/当前日期/时间/地点` 元数据，则允许它继续向前推进；已存 timeline / current state 只作为历史兜底，且不得把状态拉回过去。
- 即使“自动增量总结”关闭，只要聊天继续产生新消息，生成前也会重新检查最近正文，避免旧 timeline 把当前状态停在前一天。
- `syncCurrentDateFromTimeline` 不再允许旧 timeline 日期把已经更新的 `current_story_date` 拉回过去。
- 新聊天允许在没有绝对日期的情况下开始；未建立日期时保持 `current_story_date = null`，首次出现可靠日期后再建立。
- 剧情起点不再强制必须是 `YYYY-MM-DD`，可留空或使用“本聊天剧情正式起点”等非日期说明。

## 2. 注入诊断界面

- 默认展示人类可读摘要：开关状态、注入长度、当前日期/时间/地点、人物/关系/近期事件/主线/阶段总结/待办数量。
- 原始注入 prompt 收进“查看原始注入文本（调试）”折叠区。
- 修复移动端“刷新注入诊断”按钮被挤成竖排的问题。
- 原始注入文本使用真实换行，不再显示字面量 `\n`。

## 3. 阶段大总结

- 新增 `stage_summaries` 章节级长期记忆层。
- 只基于当前 SMM 已确认的长期记忆生成，不重新全量扫描原始聊天，不修改 JSONL。
- 至少积累 6 条有效 timeline 且无大段时间线断档后才允许生成。
- 生成时按现有 timeline 分组，再由总结模型识别 1–3 个真实剧情阶段；长聊天最终保留最多 15 个宏观阶段。
- 阶段总结保留：标题、剧情概括、source 范围、日期范围、关键事件、关系变化、阶段结束状态、仍有效线索。
- 生成失败时保留旧阶段总结，不覆盖已有数据。
- 主模型注入只选少量阶段摘要（首阶段 + 最近阶段），避免重新膨胀成规则说明书。

## 升级原则

不需要全量重建，不需要重新读取初始变量，不需要清空旧记忆。升级后先正常使用并检查当前时间状态；需要大总结时，在“阶段大总结”区域手动点击“生成 / 更新阶段大总结”。

独立总结 Profile 的 Chat Completion 判定改用 SillyTavern 实际 API 映射；长聊天阶段总结提高单组输出预算并缩小分组，减少格式漂移与截断。
