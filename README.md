# Story Memory Manager v0.11.57 HYBRID

## v0.11.57 缩短生成时的记忆提示

- 已确认身份和角色查证的知识排在结构化提示最前面。
- 控制注入正文长度在约 8500 字符内；按优先级移除较旧的背景内容。
- 这是本地生成提示改动，不会重新总结历史，也不会调用独立 API。
- 本地模拟通过；最终请求中的位置和模型采用情况须在你的 SillyTavern 环境确认。

## v0.11.56 修复“总结存在但角色读取不到”

- 历史补总结尚未完成时，不再关闭全部记忆注入；已确认部分继续提供给主模型。
- 注入真实 `facts`，不再只注入 semantic anchors。
- 身份、血缘、身世、调查、查证、角色已知信息提升为长期关键事实。
- 关键事实不会因超出最近时间线窗口而消失，并明确禁止角色无故遗忘或否认。
- 安装后从已有时间线本地补提关键事实，不调用 API、不推进游标。

## v0.11.55 预设剧情日历成为日期最高权威

- 识别回复中的 `STORY CALENDAR / 灰烬日历`，读取选中日和日历事件所属日期。
- 同楼日历日期优先于总结模型根据星期自行推算的日期。
- 安装后自动用日历本地回修已总结时间线，不调用 API、不改变扫描游标。
- 清除误写入时间线的 `SMM-LINES-1` 协议标题。
- 日历无法给出具体公历日时，保留原文的节气/农历提示，不自行换算。

## v0.11.54 独立 API 改用普通文本行协议

- 直接外部 API 不再要求模型生成 JSON，改为简短的 `SMM-LINES-1` 分行摘要。
- 插件在本地将 T/F/P/N/R/C 行转换为原有长期记忆结构，不改变既有记忆架构。
- 仍然每批只请求一次；本地转换不会追加 API 调用，失败不写入且不推进游标。
- 兼容模型偶尔仍返回的旧 JSON，并保留 v0.11.53 的粘连 JSON 恢复。

## v0.11.53 修复同一响应中JSON重新开头/粘连

- 修复模型在某个字符串尚未结束时再次输出 `{"story_start":...}`，导致两份JSON粘连的问题。
- 检测多个根JSON开头，优先从后往前提取最新的完整对象；提取和修复均在本地完成，不增加API调用。
- 直接API的输出骨架改为 timeline-first：只有 timeline 是必填核心字段，其余长期记忆分类按本批变化选填。
- 长期记忆存储、人物/NPC、关系、事件、物品、地点、主线和语义锚点结构均保留；只是避免要求模型每批重复输出所有空字段。

## v0.11.52 本地恢复可追溯时间线

- 修复“API HTTP 200、JSON可用，但 timeline 为空或 source 不在本批范围”导致整批付费结果被拒绝的问题。
- 提示词明确要求：存在剧情内容时 timeline 至少一项，facts/events 不能替代 timeline。
- 如果模型把本批编号写成相对编号 `#1～#15`，插件会严格映射到当前真实楼层范围。
- 如果 timeline 为空，插件会从同一次响应中带有效 source 的 events、semantic_anchors、facts、relationships、NPC记录依次恢复时间线。
- 本地恢复不调用API；恢复后仍需通过原有楼层范围与提交校验。没有任何可追溯来源时仍拒绝写入。

## v0.11.51 本地修复模型返回的残缺 JSON

- v0.11.50 已确认直接 API 能返回总结，但模型可能漏写数组元素之间或对象字段之间的逗号。
- 新增第二阶段本地 JSON 修复：根据解析错误位置补逗号、补错位的 `]`/`}`，并补齐末尾缺失括号。
- 修格式完全在浏览器本地执行，不会再次调用 API，也不会产生第二次费用。
- 严格 JSON 和原有的引号修复路径保持不变；只有两者都失败时才启用新的分隔符修复。
- 修复后仍需通过原有 source、时间线和提交校验；校验失败仍不写入记忆、不推进游标。

## v0.11.50 严格修复直接 API 不稳定路径

- 对照 Memory Palace 实际源码，直接 API 请求体只保留 `messages` 和可选 `model`，不再发送 Schema、response_format、preset、max_tokens 等兼容性不确定字段。
- 移除直接 API 的120秒强制中断；已经付费的慢请求会继续等待服务商返回，不再由 SMM 提前丢弃结果。
- 外部 API 使用短版增量提示词，只携带压缩长期记忆与本批未处理正文；已处理旧正文不会重复发送。
- 历史补总结每批最多15条，以约36,000输入 tokens为目标自适应；特别长时才会少于15条。后续自动总结仍为最多10条。
- 每次直连请求记录匿名请求编号、实际等待时间、HTTP状态和请求大小，便于区分插件错误与服务商520/524。
- 一次点击仍然只调用一次；无自动重试，失败不写入记忆、不推进游标。

注意：SMM可以消除自身120秒误杀和请求体不兼容，但无法修复 `astroflowing` 源站自身返回的 Cloudflare 520/524。

- 已成功推进游标的旧楼层不会作为原始聊天再次发送；API只处理仍待总结的楼层，并携带压缩长期记忆用于连续性。
- 保持费用保护关闭：自适应是超时优化，不会因超过目标而阻止单条消息；仍为一键一次请求、无自动重试、失败不写入且不推进游标。

本版继续使用 SillyTavern 当前聊天模型做一次静默语义总结，并参考 [SillyTavern Memory Palace](https://github.com/badcode1024-tech/sillytavern-memory-palace) 的结构化总结与 NPC 分区思路：主要人物保留完整状态，次要 NPC 单独保存极简档案，并且只在当前剧情命中时注入。

## v0.11.41 独立 API 费用熔断与 Cloudflare 520 防护

- 独立 Profile 每次点击“总结新增”最多发送 **1 个付费批次**，不会在一次点击中连续处理全部积压楼层。

> 熔断只能防止后续重复扣费，无法撤销供应商对已经发出的第一次请求计费。Cloudflare 520 属于 API 源站异常，应先联系供应商处理。

## v0.11.37 结构化语义总结与 NPC 独立记忆

- 当前模型静默请求现在会同时收到完整 JSON Schema，明确要求所有字段、空值格式和 `npcs` 结构；仍然每批只调用模型一次，不增加 JSON 修复重试。
- 新增“语义总结而非逐楼摘抄”规则：连续 USER/CHARACTER 往来合并为少量完整事件，保留参与者、关键行动、因果、结果与状态变化；玩家的提议/询问不会自动被写成已完成事实。
- 新增独立 `npcs` 记忆库。NPC 只保存姓名、身份、一句话关键简述、当前状态、别名和真实 source，不再与主要人物档案混在一起。
- 写入前执行确定性分类：当前玩家与当前角色永远不是 NPC；角色卡/世界书候选名在真实正文至少重复出现两次才视为主要角色；其他实际登场的次要人物归入 NPC。
- NPC 必须引用当前批真实楼层。世界书未来人物、隐藏规则、模板 NPC 或越界 source 会被拒绝，不会进入 canonical memory。
- 主模型生成时只注入最近正文或当前场景命中的 NPC，最多 6 个；未被提及的旧 NPC 不占上下文。
- “查看 / 收起记忆”、历史搜索、注入诊断和 v4 兼容视图均新增 NPC 分区与计数。

若旧版已经写入错误的 0 API 玩家原句，仍请先点“撤销错误 0 API 记录并重新排队”，再用“总结新增（当前模型）”重新总结。原始 JSONL 与剧情起点不会被修改。

## v0.11.36 当前模型静默总结

- 每批同时读取用户与角色的真实正文，不再把角色卡渲染出来的“摘要卡片”或本地拼句当作完整语义总结。
- 默认每批最多 30 条，每批严格只生成一次；JSON 围栏、尾逗号等常见问题由本地修复，不再发起第 2/3 次模型请求。
- 只有 JSON 可解析、timeline 非空且 source 能追溯到本批真实楼层时才写入并推进游标。
- 非 JSON、空响应、Cloudflare 524、120 秒超时或 source 校验失败时，本批仍保持待总结；不会本地保底、不会自动切换 0 API，也不会隐藏该批楼层。
- 默认总结方式迁移为“当前聊天模型（推荐，无需独立 API）”。旧 0 API 规则抽取仍保留为实验性维护工具，但不再推荐用于完整长期记忆。
- 新增“撤销错误 0 API 记录并重新排队”：从最早旧本地记录起撤销派生记忆、回退处理游标并保存撤销备份；剧情起点和原始聊天 JSONL 不变。

## v0.11.31 无依据分钟降级

- timeline 的具体钟点必须能在同 source 的 canonical 正文或允许的同楼状态元数据中得到验证；预设摘要不能用自己生成的时间反向证明自己。

- 被降级的分钟不再参与同日倒退、跨午夜、事件排序或后续时间推算，避免一个早期猜测持续污染整条时间线。

- 至少积累 6 条有效 timeline 且无大段时间线断档后才允许生成。
- 生成时按现有 timeline 分组，再由总结模型识别 1–3 个真实剧情阶段；长聊天最终保留最多 15 个宏观阶段。
- 阶段总结保留：标题、剧情概括、source 范围、日期范围、关键事件、关系变化、阶段结束状态、仍有效线索。
- 生成失败时保留旧阶段总结，不覆盖已有数据。
- 主模型注入只选少量阶段摘要（首阶段 + 最近阶段），避免重新膨胀成规则说明书。

## 升级原则

不需要全量重建，不需要重新读取初始变量，不需要清空旧记忆。升级后先正常使用并检查当前时间状态；需要大总结时，在“阶段大总结”区域手动点击“生成 / 更新阶段大总结”。
