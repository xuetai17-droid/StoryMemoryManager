# Story Memory Manager v0.11.31 HYBRID

本版在 v0.11.30 双时间轴修复上继续收紧时间精度：没有旧摘要、原文也没有具体钟点的楼层，不再保留模型补出的精确分钟。保留 0 API、30 条批次、自动剧情起点、地点保护和 Cloudflare 524 保底；不修改原聊天 JSONL。


## v0.11.31 无依据分钟降级

- timeline 的具体钟点必须能在同 source 的 canonical 正文或允许的同楼状态元数据中得到验证；预设摘要不能用自己生成的时间反向证明自己。
- 旧记忆中的 `下午3:00（总结推测时间）` 若找不到原文依据，会在升级后首次刷新自动降级为 `下午（具体时刻未明确）`；完全无法确认时显示 `时间未明确`。
- 原文明示的 `15:20`、`下午3:30—5:00` 等仍完整保留，并继续标记为“原文明确时间/原文时间范围已验证”。
- 被降级的分钟不再参与同日倒退、跨午夜、事件排序或后续时间推算，避免一个早期猜测持续污染整条时间线。
- MVU 现实钟只能验证现实时间轴；当事件已处于 2003 等独立场景日历时，2026 现实钟不会成为该事件的精确剧情钟点。
- 没有摘要的旧事件若紧邻后续第一个可靠的 2003 场景锚点，不再错误留在遥远的 2026 开场桶中；仅按 source 邻近性继承场景日期，并明确标记为“邻近场景日期”，仍不补具体钟点。
- 迁移只修改 SMM timeline 的时间精度与证据标签，保留日期、事件文字、人物、关系、source、处理游标和原始 JSONL；全程 0 API。


## v0.11.30 场景日历与现实钟分离

- `story_start` 只表示不可漂移的剧情开场，不再被当作以后所有 timeline 日期的最小值。聊天可按 source 顺序从 2026 开场进入 2003 历史副本/模拟场景。
- `timeline.date`、`current_story_date/current_story_time` 采用当前正在演出的剧情场景时间；`/世界/现实时间` 另存为 MVU 现实时间轴，不再覆盖预设剧情摘要中的完整场景日期。
- 0 API 管线在同一 source 内采用预设末尾 `<abstract>/<plot>` 的场景日期和地点；其中的精确钟点还必须通过 v0.11.31 的原文/同楼状态证据检查。
- 升级后首次刷新会按现有 timeline 的真实 source 本地校正错误日期/时间。只修改 SMM 记忆中的时间字段，不改事件文字、人物、关系、处理游标或原始聊天，也不调用 API。
- 时间线浏览器改为按原聊天 source 顺序展示日期段，不再按年份排序而把 2003 场景移到 2026 开场之前。
- 当前状态优先采用最新“即时状态/当前状态”或预设剧情摘要；因此最新状态为 `2003-10-28 13:45` 时，不会继续停在较早的 `12:05`。


## v0.11.29 0 API 增量总结与双日历修复（历史记录；日期归属已由 v0.11.30 替代）

- 新增“总结方式”：默认为“0 API 本地事实”，日常“总结新增”和自动增量总结均不发出模型请求。
- 本地模式优先压缩回复中已有的 `<abstract><plot>` 等结构化剧情事实；没有摘要时，只保守抽取原文中可直接确认的强事实，不自行编剧。
- 无法安全本地压缩的楼层会记入 deferred 范围，不会被自动隐藏；已成功的本地批次会独立保存并推进游标。
- 默认每批从 20 条调整为 30 条；升级时仅将仍保持旧默认 20 的设置迁移到 30。
- 带后缀说明的自动剧情起点（如 `2026-04-01 / 第一次洗牌·中心广场开场`）现在能在本地总结、日期校准和安全重建中正确提取日期部分。
- AI 模式仍可手动选择。检测到 Cloudflare 524 或客户端 120 秒超时后，不再进行第 2/3 次 JSON 兼容请求；当批直接本地保底，后续批次自动切回 0 API。
- 只要聊天已出现可识别的 `/世界/现实时间`，`timeline.date` 和 `current_story_date/current_story_time` 必须归属现实主轴。像 `2003-10-15` 这样早于聊天起点的副本日历会保留为 `[场景第二时间轴·2003-10-15 …]`，不再把顶部日期拉回 2003 年。
- `current_scene` 中的“未建立/未知/空值”不再覆盖上一批已确认地点；升级后可从最近时间线、世界状态或明确地点正文本地恢复。
- 阶段大总结尊重当前总结方式：0 API 时直接使用已确认 canonical timeline，不先试调模型。


## v0.11.28 剧情起点自动初始化

- 新聊天无需手动填写剧情起点；首次增量总结前自动从开场正文、`<date>` 或世界级时间变量中建立。
- MVU 双时间轴卡优先采用 `/世界/现实时间`，不会把副本第几天当成绝对剧情日期。
- 开场没有可靠绝对日期时仅建立“本聊天剧情正式起点”，不自行编造日期。
- 剧情起点改为严格按聊天保存，不再将上一聊天的手动值作为新聊天默认值。
- 已经建立记忆的旧聊天保持原剧情起点不变，不重建、不修改聊天 JSONL。


## v0.11.27 MVU 双时间轴修复

- 新增 `/世界/现实时间`、`/世界/现实日期` 白名单读取，兼容 `JSONPatch` 与外层 `UpdateVariable`；仍不会把完整变量块当作 canonical 正文。
- `/世界/现实时间` 可同时解析 `YYYY年MM月DD日 HH:MM` 中的绝对日期与现实钟点，并被标记为“现实主时间轴”。
- `玩家副本.副本内时间`、`考官副本.副本内时间` 等局部时钟不会进入主时间字段；它们可以继续保留在 timeline 的显示文字中。
- 现实主时间轴允许经过校验的单向多日推进，例如第一次洗牌 4 月 1 日进入第二轮 4 月 8 日，不再因缺少“七天后”正文而被锁回剧情起点。
- 同一楼层同时出现现实时间和副本时间时，`current_story_date/current_story_time` 采用现实时间；timeline.time 可保留“副本第 N 天 HH:MM”作为第二时间轴。
- 升级后自动对已有 timeline 做一次仅限日期轴的本地校准；不重新请求 AI、不全量重建、不清空人物关系，也不修改原聊天 JSONL。
- 日期倒退仍被拦截；没有 `/世界/现实时间` 的普通角色卡继续沿用 v0.11.26 的保守单时间轴规则。



## v0.11.26 阶段大总结稳定性收口

- 阶段大总结改为“一个确定窗口 = 一个宏观阶段”的稳定管线，不再要求模型返回 `stages` 数组或自行切 1–3 段，避免不同后端把根对象/数组包装成不同形态。
- 单组最多 30 条已确认 timeline；source 范围、日期范围由 SMM 本地确定，模型不再负责边界字段。
- 兼容模型直接返回单个阶段对象、`stages`/`chapters` 数组以及常见 `value/data/result` 包装。
- 每一组独立容错：模型输出为空、非 JSON、字段包装异常、Profile 请求失败或超时，都不会再让整次 1700+ 楼阶段总结报废。该组会切换为“本地事实保底”，只从现有 canonical timeline/open_loops 抽取，不编造新事实。
- 连续两组 AI 输出异常时，本轮开启熔断：剩余窗口直接使用本地事实保底，避免反复烧 Token 和连续弹错；下一次手动“更新阶段大总结”会重新尝试 AI，可把保底阶段升级为 AI 阶段。
- 阶段浏览器会标记“本地事实保底”，便于人工核对；主模型注入格式不变。
- 失败安全边界不变：不重扫原聊天、不修改 JSONL、不清空旧 memory；只有完整阶段集合构建完成后才一次性写入。


## v0.11.24 独立总结结构化输出与预设隔离

- 独立总结 Profile 请求不再加载保存的聊天/RP generation preset，避免角色扮演预设干扰 JSON-only 总结任务。
- Chat Completion Profile 在提供 `jsonSchema` 时把 schema 透传给 SillyTavern `ConnectionManagerRequestService.sendRequest(..., overridePayload)`，启用原生结构化 JSON 请求。
- 兼容 SillyTavern 在结构化输出时把 `response.content` 直接返回为对象的情况，会安全序列化后交给现有 JSON 校验链。
- 保留 v0.11.23 的 reasoning JSON 恢复作为兜底；reasoning 只有普通推理文本时仍不会写入长期记忆。
- 不改动原聊天 JSONL，不重建旧记忆，不改变 v0.11.21 已通过的剧情时间/地点解析。

## v0.11.23 独立总结 Profile 空正文热修复

- 修复独立总结 Profile 请求成功、但 SillyTavern 将结果放在 `reasoning` 而 `content` 为空时，SMM 误报“Profile 返回为空”的问题。
- SMM 仍优先读取最终 `content`；只有最终正文为空、且 reasoning 中存在可本地解析/修复的 JSON 对象时，才将 reasoning 作为恢复来源。
- 不会把普通推理 prose 直接写进 canonical memory；reasoning 不能解析为 JSON 时仍按失败处理并保留旧结果。
- 同时兼容 `message.content`、`choices[0].message.content` 等非标准包装，避免对象型 `message` 被错误转换成 `[object Object]`。
- 不改 v0.11.22 已通过的时间/地点追踪、界面和阶段总结结构。

## v0.11.22 阶段大总结 JSON 热修复

- 修复阶段大总结模型在 `summary` 等文本字段中输出未转义 ASCII 双引号时，`JSON.parse` 与旧本地修复均失败的问题。
- 本地修复现在会识别“字符串内容里的裸双引号”和真正的 JSON 结构闭合引号，只转义前者。
- 不再全局把中文弯引号 `“ ”` 转成 ASCII 双引号，避免原本合法的中文引用反而被修坏。
- 阶段大总结提示增加标准 JSON 约束：引用称呼/原话优先使用 `「」` 或中文弯引号，降低后端再次产生裸双引号的概率。
- 阶段大总结失败提示改为短错误摘要；完整响应预览只保留在浏览器控制台，避免手机端出现覆盖大半屏的红色错误块。
- 该修复不会重扫原聊天、不会清空 memory、不会修改 JSONL；失败的这一次没有写入阶段总结，可升级后直接重新点击生成。

## 1. 当前剧情时间 / 地点追踪

- 新增轻量 current-state resolver：同一/相邻状态证据优先采用最近可靠 canonical 正文；如果后续楼层只有可靠 `/世界/当前日期/时间/地点` 元数据，则允许它继续向前推进；已存 timeline / current state 只作为历史兜底，且不得把状态拉回过去。
- 即使“自动增量总结”关闭，只要聊天继续产生新消息，生成前也会重新检查最近正文，避免旧 timeline 把当前状态停在前一天。
- `syncCurrentDateFromTimeline` 不再允许旧 timeline 日期把已经更新的 `current_story_date` 拉回过去。
- 新聊天允许在没有绝对日期的情况下开始；未建立日期时保持 `current_story_date = null`，首次出现可靠日期后再建立。
- 剧情起点不再强制必须是 `YYYY-MM-DD`，可留空或使用“本聊天剧情正式起点”等非日期说明。

## 2. 注入诊断界面

- 默认展示人类可读摘要：开关状态、注入长度、当前日期/时间/地点、人物/关系/近期事件/主线/阶段总结/待办数量。
- 原始注入 prompt 收进“查看原始注入文本（调试）”折叠区。
- 修复移动端“刷新注入诊断”按钮被挤成竖排的问题。
- 原始注入文本使用真实换行，不再显示字面量 `\n`。

## 3. 阶段大总结

- 新增 `stage_summaries` 章节级长期记忆层。
- 只基于当前 SMM 已确认的长期记忆生成，不重新全量扫描原始聊天，不修改 JSONL。
- 至少积累 6 条有效 timeline 且无大段时间线断档后才允许生成。
- 生成时按现有 timeline 分组，再由总结模型识别 1–3 个真实剧情阶段；长聊天最终保留最多 15 个宏观阶段。
- 阶段总结保留：标题、剧情概括、source 范围、日期范围、关键事件、关系变化、阶段结束状态、仍有效线索。
- 生成失败时保留旧阶段总结，不覆盖已有数据。
- 主模型注入只选少量阶段摘要（首阶段 + 最近阶段），避免重新膨胀成规则说明书。

## 升级原则

不需要全量重建，不需要重新读取初始变量，不需要清空旧记忆。升级后先正常使用并检查当前时间状态；需要大总结时，在“阶段大总结”区域手动点击“生成 / 更新阶段大总结”。


### v0.11.25 阶段大总结兼容修复
独立总结 Profile 的 Chat Completion 判定改用 SillyTavern 实际 API 映射；长聊天阶段总结提高单组输出预算并缩小分组，减少格式漂移与截断。
