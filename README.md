# Story Memory Manager v0.11.6

本版继续完善 0 API 代码补档，重点修复两件事：

1. v0.11.5 在没有结构化摘要时仍可能把原始对白/细节大段塞进 timeline。
2. 重建缺口后，缺口后方已经存在的旧 timeline（例如 #1623+）仍可能显示“未明确 / 时间无法验证”。

## 推荐操作

1. 自动增量总结：关闭。
2. 生成时注入剧情记忆：关闭。
3. 总结后自动隐藏：关闭。
4. 打开 `更多工具 → 历史重建 → 补总结缺失楼层`。
5. 使用原补档范围，例如 `1489 → 1622`。
6. 点击 **代码压缩重建这个范围（0 API）**。

该按钮会：

- 替换目标范围内上一版代码补档的 timeline；
- 结构化拆分 `<abstract>/<meow_FM>`；
- 对 event 做本地事实压缩，尽量控制为约 60–190 字，不再保留大段对白；
- 不调用总结 API；
- 不改原聊天；
- 不改变 `last_processed_index`；
- 不重写人物、关系、主线、待办、当前场景；
- 重建后继续扫描至当前已处理游标，只填补已有 timeline 的“未明确时间/日期/地点”；并从最新已处理楼层的世界状态元数据同步顶部 `current_story_time`（日期只允许向前，场景 location 仅同步同源最新地点）。

## 单独修复旧时间

历史重建区域新增：

**仅修复时间线“未明确时间”（0 API）**

它扫描当前 timeline，只使用每条事件自己 `source` 对应的原始消息：

1. 优先读取同 source assistant 回复的 `/世界/当前日期`、`/世界/当前时间`、`/世界/当前地点`；
2. 再尝试同 source 的结构化 `<abstract>` 时间；
3. 最后才读取同 source 原文中的明确钟点。

已有明确时间不会被覆盖，也不会使用后续无关楼层的时间倒灌。

## 限制

0 API 模式是确定性的事实抽取，不等价于 LLM 总结。它不会主动推理人物关系、人物锚点、主线、待办或隐含因果。复杂场景的压缩质量会低于模型总结，但应明显短于原始正文，并保持 source 可追溯。
