# Story Memory Manager v0.11.5

本版用于修正 v0.11.4 的 0 API 补档显示质量：预设 `<abstract>` 内多条编号记录会被拆成独立 timeline，而不是整块复制。

## 推荐用法

1. 自动增量总结：关闭。
2. 生成时注入剧情记忆：关闭。
3. 总结后自动隐藏：关闭。
4. 打开 `更多工具 → 历史重建 → 补总结缺失楼层`。
5. 如果 v0.11.4 已经补过，v0.11.5 会自动回填上一次代码补档范围；否则手动输入，例如 `1489 → 1622`。
6. 点击 **代码补档 / 重建这个范围（0 API）**。

如果这个范围之前已经用 v0.11.4 做过代码补档，v0.11.5 会先替换该范围内旧的代码补档 timeline，再重新生成，不需要手工删除。

## 结构化摘要示例

输入：

`049 2025-09-23 | 12:55-13:00 意式餐厅Bistro 19·二楼包间 薛伶……；050 2025-09-23 | 13:00-13:10 KΣ宅邸 薛伶……`

会拆成两条独立 timeline：

- `12:55-13:00` + 第一事件
- `13:00-13:10` + 第二事件

编号、日期、时间不会重复塞进 event 正文。

## 限制

0 API 模式只做可追溯 timeline 补档/重建，不等价于 LLM 总结。它不会主动推理人物关系、人物锚点、主线、待办或隐含因果。
