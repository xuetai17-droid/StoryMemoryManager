# Story Memory Manager v0.5.8 日期段保留 / 日期岛修复版

修复 v0.5.6 的“全部合并成第一天”问题。

新算法：
- 已有连续日期段默认保留，不再从剧情起点向后强制继承同一天。
- event.date 作为“软日期标签”参与分段，但不作为绝对真相。
- 只自动修复“日期岛”：
  A日连续段 → B日小段 → A日连续段，
  且 B 日小段没有明确绝对日期、次日/第二天/翌日、跨午夜/零点等证据，
  则把 B 日小段归回 A 日。
- 同一天内仍以 source 原始消息编号为主顺序。
- “凌晨/半夜”本身不触发换日。
- 不修改原始聊天。

目标案例：
9月11日 source #67... → 错误的9月12日 #71-#79 → 又回到9月11日 #80...
会被识别为日期岛并把 #71-#79 拉回9月11日；
同时真正的9月10、9月11、9月12等连续日期段不会被全部合并。
