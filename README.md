# Story Memory Manager (SMM)

面向 SillyTavern 长篇 RP / 连续剧情的结构化长期记忆扩展。

当前版本：**v0.11.1（核心连续性实验版）**

## 核心功能

- 自动增量总结旧聊天，并将剧情压缩为结构化长期记忆。
- 保留最近原始聊天作为短期上下文。
- 可在安全记忆注入开启后自动隐藏已总结旧楼层，减少发送给模型的历史上下文。
- 维护剧情时间轴、人物、人物关系、关键事实、事件与连续性语义锚点。
- `semantic_anchors` 用于保护事件性质、因果、主动/被动关系及明确意愿状态，避免摘要压缩改变历史事件性质。
- 严格区分剧情事实与 OOC / 重写 / 文风 / 格式等元指令。
- 支持独立 Connection Profile 作为总结模型。
- 提供记忆导入、导出、日期校准、安全历史重建及隐藏楼层恢复工具。

## v0.10.8 延续的事项策略

`open_loops` 只作为后台的“仍然有效的未来连续性事项池”，不再作为用户需要长期维护的任务列表。

- `pending` / `at_risk` 明确过期后会从活动事项池删除。
- `in_progress` 不会仅因为同一天的开始时间已过去就删除；如果跨到后续日期仍未关闭，则会清理。
- `completed` / `cancelled` / `missed` / `superseded` / `invalidated` 会直接从活动事项池移除。
- 旧 `closed_loops` 会迁移为最多 80 条的轻量 tombstone，仅用于防止同一旧事项被总结模型重复“复活”。
- tombstone 不保存完整事项描述，不显示在 UI，也不会注入主聊天模型。
- 已发生且重要的剧情结果应由 `timeline` / `events` / `relationships` / `semantic_anchors` 保存，而不是靠历史待办列表保存。

## v0.11.0：核心连续性恢复

本版本针对长篇 RP 中“剧情越来越像流水账、人物说话变味、辅助小剧场污染长期记忆”的问题做结构修复：

- 总结前只把真正剧情正文送入 SMM；优先提取 `<content>`，并排除 thinking、HTML 草稿注释、故事考据、campus_gossip、UpdateVariable、Analysis、JSONPatch 等辅助块。
- 新增 `character_anchors`，保护核心人物的说话方式、决策模式、情绪表达、边界与关系互动方式。角色卡/世界书仍是基础人设最高优先级。
- 新增 `active_arcs`，只保留 3-6 条真正仍在发展的宏观主线，避免长期记忆把“吃饭/洗澡/睡觉/通勤/上药”等日常微动作误当成剧情主轴。
- 总结与主聊天注入改用“trusted-core”记忆视图，不再把旧 `facts`、隔离项、冲突、物品和完整 current_scene note 反复喂回模型，降低已有污染自我强化。
- `current_scene` 改为当前快照覆盖，不再把旧 note 永久叠加。
- 物品拆分 `owner / holder / user / location / source_owner`；没有明确赠予/转让证据时，普通使用或持有不会改变 owner。

这是一次面向长篇连续性的结构调整。建议升级后先关闭自动隐藏，手动总结一批新消息并检查“当前主线 / 核心人物锚点”，确认正确后再恢复全自动。

## 历史事实防补写

SMM 会明确告诉总结模型和主聊天模型：

- 过去已经发生的具体对话、约定、物品来源、动机、关系历史、主动/被动以及同意/拒绝状态，必须有近期正文、可靠长期记忆或 `semantic_anchors` 支持。
- 不能为了叙事连贯，自行把不存在的过去细节补成既定历史事实。
- 当前回复可以有不影响连续性的文学性描写，但这些装饰性细节不应反向污染历史记忆。

这能降低“重新输出时凭空增加过去细节”的概率，但任何基于 LLM 的总结仍可能出错，建议偶尔使用“查看 / 收起记忆”核对时间线和人物关系。

## 记忆查看界面

日常记忆视图只保留适合人工核查的内容：

- 历史记忆浏览器
- 时间线
- 人物
- 人物关系
- 关键连续性语义锚点

`open_loops`、隔离项、冲突、当前场景、audit 等内部数据继续在后台工作，但不占用日常移动端界面。



- 移动端设置区重新分组：日常自动管理集中在一个紧凑卡片里，总结模型与总结节奏默认折叠。
- 保留“查看 / 收起记忆”，用于人工核对时间线、人物关系和语义锚点。
- 对聊天正文中的远程图片加载失败增加纯前端容错：隐藏浏览器裂图图标并显示简洁占位提示。

## 安装

### 方式一：SillyTavern 扩展安装器

将 GitHub 仓库 URL 填入 SillyTavern 的第三方扩展安装入口，然后重启 / 刷新 SillyTavern。

### 方式二：手动安装

把仓库内容放入：

```text
data/default-user/extensions/StoryMemoryManager/
```

目录中至少应包含：

```text
index.js
style.css
manifest.json
```

然后重启或完整刷新 SillyTavern。

## 首次使用建议

新安装默认不会自动开始处理剧情。建议按以下顺序配置：

1. 设置剧情起点（`YYYY-MM-DD`）。
2. 启用插件。
3. 配置总结模型；可使用当前模型，也可以建立独立 Connection Profile。
4. 先手动执行一次“总结新增”，检查记忆是否正确。
5. 开启“自动增量总结”。
6. 开启“生成时注入剧情记忆”。
7. 确认长期连续性正常后，再开启“总结后自动隐藏旧楼层”。
8. 建议保留最近原文 30 楼起步，根据自己的上下文预算调整。

自动隐藏前建议先备份聊天。

## 自动隐藏

自动隐藏只在安全记忆注入启用时允许开启。

隐藏后的旧楼层仍保留在原聊天数据中；SMM 提供“恢复全部隐藏楼层”按钮。SMM 的正常升级不应修改或重写聊天正文 JSONL。

## 总结模型

支持：

- 跟随当前聊天模型；
- 独立 Connection Profile；
- 独立 Profile 失败后暂停；
- 或按设置回退当前聊天模型。

对长篇聊天，建议给总结使用稳定、结构化输出能力较好的模型。

## 记忆结构

当前 canonical memory 主要包含：

```text
story_start
current_story_date
current_story_time
current_scene
timeline
facts
events
characters
relationships
open_loops
locations
items
conflicts
quarantined
semantic_anchors
character_anchors
active_arcs
audit
```

另有内部兼容字段 `closed_loops` 与 `loop_tombstones`；v0.10.8 延续该策略：旧 closed loop 历史会压缩为轻量 tombstone。

## 连续性原则

- 时间主线原则上单向推进。
- AI `<date>` 标签只是低优先级候选证据。
- 没有可靠跨日 / 跨月证据时，不自行推进日期。
- 回忆旧事件不能让当前主线日期倒退。
- 地点变化、衣着变化、关系发展、计划改变等正常剧情演进不应被当作 conflict。
- `quarantined` 仅用于真正可能污染长期连续性的可疑事实。
- 用户元指令不进入长期剧情记忆。

## 升级

直接替换扩展文件即可。聊天 metadata 会继续保留，不需要重新重建聊天，也不需要修改 JSONL。

从 v0.10.5 / v0.10.6 升级后，下一次记忆 normalize / merge 时：

- 旧 `closed_loops` 会迁移为轻量 tombstone；
- 已过期活动事项会按 v0.10.6 规则清理；
- 已有 timeline、人物关系和语义锚点继续保留。

升级前仍建议备份扩展目录和重要聊天。

## 已知限制

- SMM 不能保证 LLM 永远不会总结错误；重要剧情建议定期人工抽查。
- 自动清理过期事项依赖可解析的日期 / 时间。没有明确时间的条件事项不会仅凭猜测删除。
- 同一天的 `in_progress` 不会因为开始时间已过自动结束，因为 SMM 不知道事项的持续时间。
- 人物别名不再包含任何特定角色硬编码；公开版依赖总结模型在上下文中保持统一人物命名。
- API 排队、代理延迟及模型服务端 TTFT 不属于 SMM 的性能控制范围。

## 发布与隐私

仓库不应包含：

- 用户聊天 JSONL；
- 导出的记忆 JSON；
- API Key；
- Connection Profile 凭据；
- 本地 `.bak-*` 备份。

公开版代码不包含特定剧情的人名、地点或事件硬编码。

## 测试环境

主要经过 SillyTavern 1.18.0、Android + Termux 以及 1400+ 楼长篇聊天的实际使用验证。

### 聊天图片说明

SMM 不处理聊天正文中的图片加载。图片是否显示由消息 HTML、图片 URL、浏览器以及对应图床/资源服务器决定。v0.10.8 不再监听或替换聊天中的 `<img>`，以避免移动端反复重绘造成闪烁。
